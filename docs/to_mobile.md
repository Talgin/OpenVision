Спасибо за подробный разбор. Пункты 2, 4, 5, 7, 8, 9 и 10 уже сделаны и выложены на 10.8.0.53. Handoff обновлён до версии 0.2, в начале есть список изменений.

**1. Боевой адрес с HTTPS/WSS.** [ЗАПОЛНИТЬ: домен и срок.] Конфигурация готова: TLS, WebSocket через прокси, внутренние методы закрыты снаружи. Не хватает сервера и DNS-записи. До этого работаем через 10.8.0.53 по HTTP, cleartext разрешаем только в debug-сборке.

**2. Удаление аккаунта.** `POST /api/v1/auth/delete-account {"password"}` → 204.
- Если вызывает владелец, удаляется вся компания. Все пользователи сразу выходят из системы, их email можно сразу использовать для новой регистрации. Камеры отключаются. Камеры, события и снимки стираются в фоне, обычно в течение минуты. Восстановить нельзя.
- Если вызывает любой другой пользователь, удаляется только его учётная запись.

Ошибки: `wrong_password` (400), `rate_limited` (429). Подробности в §4 handoff.
Проверяйте, пожалуйста, на своей учётной записи, а не на demo@openvision.dev: она общая.

**3. Firebase и отправка push.** [ЗАПОЛНИТЬ: доступ к проекту и срок.] Формат data-сообщения не меняется: §9 handoff.

**4. Сброс пароля сотрудника.** `POST /api/v1/users/{id}/password {"new_password"}` (право `users.write`) → 204. Сотрудник выходит на всех устройствах, новый пароль администратор передаёт ему сам. Для владельца и для самого себя метод не работает (`owner_protected` / `self_protected`). Восстановление по почте будет позже, нужен почтовый сервис. До этого на экране входа «Забыли пароль?» можно отвечать «обратитесь к администратору».

**5. Edge-агент.**
- `POST /api/v1/edge-agents/{id}/rotate-token` → `{"token", "install_command"}`, показывается один раз. Старый токен перестаёт работать сразу, агента нужно переустановить новой командой. Камеры при этом не отключаются и возвращаются, когда агент снова подключится.
- Переименование: `PATCH /api/v1/edge-agents/{id} {"name"}`.

**6. Сервер 10.8.0.53.** Проверил на нём:
- demo@openvision.dev и viewer@openvision.dev входят, пароль demo-password-1;
- ссылки на картинки ведут на http://10.8.0.53:8000;
- /api/v1/live работает: после auth приходят ready и события.

**7. null в PATCH.** Отсутствующее поле не меняется. `"location": null` очищает поле. `null` в `name`, `enabled` и `source_url` возвращает 422 `validation_error` с указанием поля. Раньше `"name": null` приводил к 500, это исправлено. То же для `PATCH /users/{id}`.

**8. Ошибки в openapi.json.** Схема `ErrorOut` (`{"error": {"code", "message", "details"}}`) теперь описана для 400, 401, 403, 404, 409, 422 и 429 на всех методах. `HTTPValidationError` из схемы убран. Клиент лучше перегенерировать.

**9. Курсор аудита.** Строка, как у событий. Курсор непрозрачный, передавайте его обратно без изменений.

**10. Внутренние методы.**
- Из публичной схемы убраны.
- Пустой токен и пустой secret не проходят (401/403), даже если на сервере они не заданы. Это покрыто тестами.
- На боевом сервере прокси отдаёт 404 на весь `/internal/*`.
- Агент теперь получает конфигурацию по `/api/v1/edge/config`. Приложению этот метод не нужен.
